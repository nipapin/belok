# Оплата карточного заказа на кассе

Если aQsi подтверждает неуспешное завершение карточной операции без результата
платежа, киоск передаёт тот же заказ через существующий механизм отложенных
заказов (`Orders/simple`). Номер, состав, сумма после скидок и списанные бонусы
сохраняются. Заказ остаётся неоплаченным до получения соответствующего
фискального чека от кассы. Кассир открывает отложенный заказ и принимает оплату.

Передача происходит автоматически, только после подтверждённой неудачи
карточной операции. Кнопки ручного перевода в отложенные на киоске нет.
Если операция успешно завершилась, используется её результат и
отложенный заказ не создаётся. Обычная кнопка отмены по-прежнему
отменяет заказ и возвращает бонусы. Гость видит только просьбу обратиться
к кассиру с номером заказа; внутренний процесс передачи ему не показывается.

При неизвестном результате платежа, потерянном ответе на отправку или ошибке
с данными результата автоматической передачи для повторной оплаты нет.
Потерянный ответ на создание отложенного заказа проверяется чтением заказа
по постоянному ID; повторный POST не выполняется. После оплаты на кассе
дополнительный чек через `Receipts/process` не создаётся.

Включённая настройка передачи наличных заказов в aQsi используется и для
карточного резервного сценария. Если передача отключена или налоговые настройки
не заполнены, задание сохраняется и киоск сообщает о необходимости проверки.

Перед публикацией требуется применить только
`024_aqsi_card_cancel_intent.sql` после резервной копии `aqsi_jobs` и проверки
`_migrations`: production-деплой сам миграции не выполняет. Поле хранит намерение
отменить заказ (и ранее отправленные запросы перевода на кассу). Исторические отменённые заказы
автоматически не восстанавливаются и не передаются.

Проверки: `npm run test:aqsi`, `npm run test:aqsi:integration` с отдельной
тестовой схемой PostgreSQL и имитацией всех запросов aQsi, а также
`node scripts/test-aqsi-browser.mjs` против локального приложения.

## Версия и удалённое обновление

Рядом с «Белок» в меню киоска отображается версия проекта из `package.json`.
Её необходимо увеличивать при выпуске новых версий. Git revision сохраняется
во внутренних данных сборки. Настройки → Терминал у кассы
показывают подключавшиеся киоски, их версии, связь, занятость заказом и
подтверждение последней команды. Можно обновить один киоск или все.

Команда хранится в `app_settings`, отдельно для всех устройств и для конкретного
киоска. Киоск проверяет её примерно каждые 15 секунд и при возвращении на экран.
При наличии корзины, оформлении заказа или активной оплате обновление откладывается.
После завершения заказа обновляется service worker, удаляется кеш приложения и
выполняется переход на свежую страницу `/kiosk`. Cookies, PIN, localStorage и
sessionStorage сохраняются. Существующая регистрация уведомлений не удаляется.
Если сети нет, команда остаётся ожидающей; админка показывает фактическое
подтверждение и версию после нового запуска. Закрытое или полностью зависшее
приложение само команду получить не сможет.

Первый переход на версию с обработчиком команд требует обычного обновления
киоска. Дальнейшие обновления можно запускать из админки. Команда предназначена
для обновления приложения и кеша; она не сбрасывает устройство или доступ к кассе.
