# Кухня и технологические карты

`/kitchen` — отдельный экран персонала с поиском и категориями. Перед началом показывается состав с исходными колонками брутто, нетто и массы готового продукта. Затем каждый шаг открывается отдельно, с кнопками «Назад» и «Далее». Кнопка «Вся карта» показывает состав и весь процесс. Переключение режима не меняет текущий шаг.

Прогресс сохраняется в браузере для каждой карты и версии. После перезагрузки выберите карту снова, чтобы продолжить. Новая версия карты начинает процесс с подготовки. После завершения можно начать приготовление заново. Это помощь в выполнении процесса; завершения не отправляются в журнал производства и не списывают складские остатки.

Таймеры настраиваются вручную в секундах. Они не извлекаются из неоднозначных записей в документе, не переключают шаг автоматически и продолжают отсчёт по сохранённому времени окончания при смене режима или перезагрузке. Кнопка «Сбросить таймер» отменяет текущий отсчёт.

`/admin/kitchen` — редактор для существующей роли ADMIN. Можно создать карту, изменить название, категорию, выход и состав, добавить или удалить шаги, изменить их порядок, загрузить фото и настроить таймеры. Изменения вступают в силу после сохранения. Для черновика допустимо отсутствие состава и шагов; для публикации нужны оба. Незавершённые добавленные строки и шаги необходимо заполнить или удалить. Конфликт двух одновременных редакторов возвращает 409 и сохраняет локальный черновик второго редактора.

Фото используют существующий `/api/upload`, папку `content` в S3/Blob-хранилище или `public/uploads` при локальном хранении. Поддерживаются JPEG, PNG, WebP, GIF до 5 МБ. Маршрут `/uploads/[filename]` позволяет отдавать локальные фото сразу после загрузки в production без перезапуска сервера. Удаление фото из шага убирает ссылку, но не удаляет объект из хранилища.

Просмотр `/kitchen`, API `/api/kitchen`, черновики и редактор доступны только роли ADMIN. Проверка роли страницы и API выполняется на сервере по действующей сессии. Посетитель без входа перенаправляется к авторизации с возвратом на кухню; пользователь с ролью USER — в меню. API возвращает 403 без данных техкарт при отсутствии доступа. В меню админки есть отдельные пункты «Кухня · приготовление» и «Кухня · техкарты». Кухня не добавлена в меню покупателей; поисковая индексация отключена.

## Источник и хранение

Импортировано 30 именованных карт из `docs/technical_cards_belok.docx`. Четыре коктейля из карты № 30 выделены в отдельные рецепты: всего 33 карты. Последний пустой шаблон пропущен. Исходные количества и формулировки сохранены без догадок; варианты состава подписаны примечанием.

8 карт первоначально являются черновиками: № 3, 4, 13, 16, 19, 24, 26 и 29. № 13 требует уточнения длительности, № 16 — температуры су-вида, № 19 содержит пустой раздел запечённого картофеля, № 24 перечисляет варианты подачи вместо последовательного процесса; у остальных отсутствует инструкция приготовления. Перед публикацией ответственному сотруднику нужно проверить и дополнить эти карты.

Начальные карты находятся в `src/data/kitchen-cards.json`. Изменения хранятся в существующей PostgreSQL-таблице `app_settings`, отдельный ключ `kitchen.card.<id>` на карту. Дополнительная миграция не нужна, но существующие миграции приложения должны быть применены. Повторный импорт обновляет только исходный JSON, не заменяя сохранённые в админке версии.

Повторный импорт: Python с установленным `python-docx`, команда `python scripts/import-kitchen-cards.py docs/technical_cards_belok.docx`.

## Проверка

`npm run build`, затем `node scripts/test-kitchen.mjs`. Проверка создаёт отдельную временную базу на локальном PostgreSQL, применяет туда миграции, проверяет API и интерфейс через Puppeteer, затем удаляет базу и загруженное тестовое фото. База из `DATABASE_URL` не используется для записи. При необходимости задайте `TEST_DATABASE_ADMIN_URL` для локального подключения с правом создания временных баз. Скриншоты проверки сохраняются в `output/kitchen-qa`.
