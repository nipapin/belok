# Заказы через @belok_chat_bot

## Что подготовлено

- Входная страница `https://belok.pro/telegram`: проверенный вход через Telegram,
  затем существующее меню, корзина, самовывоз/доставка и текущие способы оплаты.
- Постоянная кнопка «🍽 Заказать» возле поля сообщения и ответ на `/start`.
- Заказы попадают в существующие заказы и на доску с источником `Telegram`.
- Бот сообщает о получении, подтверждении, приготовлении, готовности, завершении
  и отмене заказа. Уведомления ставятся в БД в той же транзакции, что изменение статуса,
  независимо от того, меняет статус доска, админка или другой обработчик.
- Telegram-покупателю создаётся отдельный обычный аккаунт без email/пароля.
  Старые аккаунты и их бонусы автоматически не объединяются: это отдельная будущая функция.

Без `TELEGRAM_BOT_TOKEN` бот отключён, обычные сайт и киоск продолжают работать.
Токен доступен только серверу. Не добавляйте его в GitHub, `NEXT_PUBLIC_*`, код,
скриншоты или команды, которые сохраняются в истории shell.

## Куда записать токен на текущем VPS (FirstVDS)

Сначала должна быть установлена версия приложения из этой ветки/PR. Само добавление
токена к старой версии не включит бота.

1. Подключитесь к VPS своим обычным SSH-пользователем с правами `sudo`.
2. Узнайте точный файл окружения production следующей командой. Она печатает
   **только пути**, без паролей или ключей:

```bash
sudo python3 - <<'PYENV'
import json
with open('/etc/firstvds-deploy/projects.json') as f:
    project = json.load(f)['belok']
for path in project.get('env_files', []):
    print(path)
PYENV
```

3. Откройте **последний** напечатанный env-файл (Node применяет их по порядку).
   Вместо `/ПУТЬ/ИЗ/КОМАНДЫ` подставьте реальный путь:

```bash
sudo nano /ПУТЬ/ИЗ/КОМАНДЫ
```

Добавьте или замените одну строку, без дубликатов:

```dotenv
TELEGRAM_BOT_TOKEN=ВАШ_ТОКЕН_ИЗ_BOTFATHER
```

`NEXT_PUBLIC_APP_URL=https://belok.pro` уже используется проектом. Если значение
другое, исправьте его и пересоберите приложение: Next.js встраивает публичные
переменные в сборку. Для стандартного production-порта 3000 больше новых
обязательных переменных нет. Не пишите токен в директорию отдельного release:
следующий деплой заменит её.

В nano: `Ctrl+O`, `Enter`, затем `Ctrl+X`. Файл с секретами должен быть доступен
только владельцу (обычно root); если необходимо, `sudo chmod 600 /ПУТЬ/ИЗ/КОМАНДЫ`.

4. Перезапустите production Belok от того пользователя, которому принадлежит PM2.
   В текущем FirstVDS receiver это root. Не перезапускайте belok-dev:

```bash
sudo -i
export PATH=/root/.nvm/versions/node/v24.14.1/bin:/usr/local/bin:/usr/bin:/bin
pm2 restart belok --update-env
pm2 logs belok --lines 30 --nostream
exit
```

Node при старте заново читает env-файлы, прописанные в PM2 `node_args` receiver.
При успехе в логах появится `Telegram bot configured`. При временной ошибке
настройка повторяется раз в минуту, сайт продолжает работать. Не присылайте
полные логи без проверки: другие подсистемы могут выводить чувствительные данные.

Интеграция автоматически применит **только** `031_telegram_orders.sql` в транзакции
с ограничением времени и advisory lock. Запуск общего `db:migrate` не нужен.
Нужны обычные права пользователя БД на создание таблиц, функций и триггеров.
Архив production уже включает папку миграций.

## Что настраивается автоматически

При старте production на порту 3000 приложение вызывает Telegram Bot API:

- `setChatMenuButton` → «🍽 Заказать» → `https://belok.pro/telegram`;
- `setMyCommands` → `/start`;
- `setWebhook` → `https://belok.pro/api/telegram/webhook` с секретом,
  вычисленным из токена (дополнительный секрет вводить не требуется).

Порт preview 3010, dev и сборка не меняют настройки бота и не отправляют уведомления.
Один токен должен использоваться только одним production-приложением.
Для нестандартного порта обновите ограничение в `shouldStartTelegramWorker` перед выпуском.
`TELEGRAM_BOT_ENABLED=false` отключает фоновую настройку и доставку уведомлений.

Нужен исходящий HTTPS-доступ VPS к `api.telegram.org` и публичный входящий доступ
Telegram к HTTPS `belok.pro/api/telegram/webhook` без авторизации/капчи.
Вручную `/setmenubutton` делать не нужно. Main Mini App в профиле бота
не обязателен для открытия через кнопку меню.

## Проверка после запуска

1. Откройте [бота](https://t.me/belok_chat_bot) и нажмите «Начать» (`/start`).
2. Проверьте приветствие и кнопку «🍽 Заказать» рядом с полем сообщения.
3. Откройте меню этой кнопкой: вход по почте не требуется.
4. Оформите небольшой тестовый заказ с оплатой наличными при самовывозе.
   Это создаёт реальный заказ — предупредите сотрудников и затем отмените его.
5. На доске должен появиться источник «Telegram» и ожидание оплаты.
   Проверьте сообщение с номером в боте, отмените заказ через админку и проверьте уведомление.
6. Онлайн-оплату/переход в банковское приложение отдельно проверьте на iPhone и
   Android с реальным эквайрингом. Это существующая интеграция сайта, а не Telegram Payments;
   повторных списаний/чеков интеграция бота сама не запускает.
7. Для готовности проверьте обычную цепочку оплаченного заказа:
   подтверждение → приготовление → готовность; бот должен сообщить о готовности.

Уведомления отправляются только в личный чат, где покупатель нажал `/start`.
Нельзя гарантировать доставку, если пользователь заблокировал бота. При 403 отправки
прекращаются до нового `/start`; временные ошибки повторяются с задержкой до 12 попыток.
Очередь переживает перезапуск. Доставка at-least-once: при потере ответа Telegram
после принятия сообщения возможен дубль, но не повторное создание заказа/оплаты.

## Замена или отключение токена

После перевыпуска в BotFather замените `TELEGRAM_BOT_TOKEN` **в том же env-файле**
и повторите перезапуск. Бот автоматически перенастроит webhook и его секрет.
До замены токена на сервере старый перестанет работать.

Для отключения удалите строку `TELEGRAM_BOT_TOKEN` и перезапустите Belok.
При необходимости удалите webhook через BotFather/Bot API. Существующие заказы сохранятся.

## Закреп в канале

Разместите пост со ссылкой `https://t.me/belok_chat_bot`. После первого `/start`
покупатель получает постоянную кнопку меню. Интеграция не публикует посты в канал.

```bash
INVENTORY_TEST_PGLITE_MODULE=/path/to/@electric-sql/pglite/dist/index.js npm run test:telegram
npm run build
```

Тесты используют изолированную БД и поддельный транспорт Telegram; production
и реальный бот не затрагиваются. До выпуска PR проверьте GitHub Actions.
