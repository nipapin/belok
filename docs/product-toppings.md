# Топпинги к блюду

В форме создания и редактирования продукта, включая «Продукты 2.0», есть блок
«Топпинги». В нём можно отметить товары из категории «Топпинги» (также
поддерживается написание «Топинги»). Цены и изображения берутся из каталога.

Кнопка «Новый топпинг» раскрывает название и цену прямо в этом блоке. После
«Создать и выбрать» товар создаётся в категории топпингов и сразу отмечается
в форме блюда; остальные несохранённые поля сохраняются. Для привязки к блюду
нужно сохранить его форму. Если категории ещё нет, она создаётся автоматически.

При добавлении блюда из меню, главной страницы, страницы блюда, карточки киоска
или окна блюда киоска открывается выбор дополнений. Разрешено несколько;
«Спасибо, не надо» добавляет только блюдо, даже если до этого были отмечены
добавки. Крестик, Escape и нажатие вне окна отменяют добавление блюда.
Повторное нажатие плюса у блюда снова предлагает топпинги.

Топпинги находятся внутри своей позиции блюда. Блюдо без добавок, с другим
набором топпингов или с другим вариантом сохраняется отдельной строкой.
Количество добавок следует количеству этой строки: 2 порции сырников со сметаной
дают 2 порции сметаны. При удалении блюда удаляются и его добавки.
В корзине сайта и киоска крестик у топпинга удаляет только его; блюдо и остальные
добавки сохраняются. Цена пересчитывается для всего количества строки. Если после
удаления строки становятся одинаковыми, они объединяются с суммированием количества.
Для чека, цен и склада топпинг остаётся отдельным товаром каталога; в заказе
его строка связана с блюдом через `parentItemId`. На кухне, в админке и в истории
добавки показываются под своим блюдом. Отметка готовности порции включает её
топпинги и не требует отмечать их отдельно.
Варианты топпинга показываются отдельными выборами со своей ценой.
Рекурсивного предложения добавок к добавкам нет.

Скрытие категории убирает её товары с витрины, но сохраняет назначенные блюдам
топпинги в окне дополнений. Купить скрытый топпинг отдельно нельзя. Товары на
стопе и товары, перенесённые из категории топпингов, не предлагаются гостю.
В админке товар на стопе остаётся в настройке,
чтобы после возвращения в продажу его не пришлось привязывать повторно.
Если доступных топпингов нет, блюдо добавляется сразу.

## Локальная проверка

Изолированная БД `belok_toppings_local` создаётся скриптом
`node scripts/toppings-local-fixture.mjs`. Скрипт разрешает подключение только
к PostgreSQL на localhost. Он создаёт тестовые сырники, кашу и добавки, применяет
миграции с учётом зависимостей складской схемы и создаёт локального администратора.
Рабочую БД и сервер скрипт не использует.

Для запуска задайте `DATABASE_URL` для этой БД, `SESSION_SECRET=toppings-local-check-only`
и `AQSI_WORKER_ENABLED=false`, затем `npm run build` и
`npm run start -- --port 3104`.

- Меню: <http://localhost:3104/menu>
- Киоск: <http://localhost:3104/kiosk>
- Настройка блюда: <http://localhost:3104/admin/products/toppings-local-syrniki/edit>
- Тестовый администратор: `admin@belok.local`, пароль `BelokLocal2026!`.

Проверки: `npm run test:toppings`, `npm run test:toppings:api`,
`npm run test:toppings:browser`. Последние две команды требуют запущенного
локального приложения с фикстурами и отказываются работать с внешним URL.
Снимки экрана сохраняются в `output/toppings-qa/`.

## Перед публикацией

Применить новые миграции `026_product_toppings.sql` и `027_order_item_toppings.sql` к целевой БД до запуска
новой версии приложения. Они создают связи блюд с топпингами и не назначают топпинги
существующим блюдам автоматически. Привязки на рабочем сайте задаются в админке.
